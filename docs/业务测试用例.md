本文是 `本体应用_上海工单` 的业务测试用例清单，由 `test/cases/` 下的用例定义自动生成。用例**按业务人员的实际使用顺序编排**：谁、在什么状态下、做什么或问什么、预期看到什么；全部在上海种子数据（`data/seed/*.csv`）上执行，MR 日统计随到达时间入库，不预置任何结论。

与 SPEC 一致性测试（DS01～DS09、问答评测，见 `测试说明.md`）的分工：那一层回答“SPEC 定义的东西是否都实现并被用到”，按 SPEC 用例（TC）组织；这一层回答“业务人员这样用，系统是否表现正确、回答是否靠谱”，按角色和工作流组织。两层共用同一套代码与数据，互不替代。

## 四、步骤与预期的写法

- **动作步骤**：某个角色通过动作入口（A_01～A_11）执行；预期要么“成功＋若干核对”，要么“被某条约束／权限／状态检查拒绝”（给出拒绝码）。拒绝也要留审计，且不产生业务记录。
- **提问步骤**：带提问者角色的口语化提问；核对意图、回答里必须出现的事实、不得出现的内容、数值与日期落地检查（每个数字都必须能在本次引用的函数结果、对象或 SPEC 规则里找到）、是否写库（只有优化本体被授权的动作可以由提问触发，且写入 1 条审计）、需要人工执行的动作是否被提示。
- **时间与外部数据**：推进时钟后，到达时间已到的 MR 日统计自动入库；MR 平台更正、资源系统变更等外部事件用明写的步骤表示。
- 回答不使用大模型，由规则按本体元数据与函数结果生成；SPEC 没有定义的内容（置信度、预测、下倾以外的措施、NR 公式）如实回答“没有定义”。
